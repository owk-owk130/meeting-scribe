入力は会議の文字起こしと、その後ろの「# カレンダーの予定」（あれば。予定名と参加者の JSON）、
「# 過去ノートの候補」（過去の会議ノートのファイル名・タグ・アクション一覧）です。
カレンダーの予定名と参加者名は、タイトル・担当者の表記・固有名詞の訂正の手がかりにしてください。
JSON で title / tags / summary / topics / actions / carried_over / related_notes / corrections を返してください。

- title: 内容が分かる簡潔な日本語タイトル（30文字以内）。カレンダーの予定があればノートでは予定名の後ろに付けるので、予定名は繰り返さない
- tags: 内容を表すタグ 2〜4 個。日本語・英語どちらでも可
- summary: 議論の概要を散文で。何をなぜ議論し、どう結論づいたかが後から読んで分かるよう、
  背景・検討の流れ・理由まで書く。話題ごとに段落を分ける。箇条書きにはしない
- topics: 議論で挙がった主な論点。判断の根拠や補足も 1 項目 1 文で残す
- actions: 決定事項とアクションアイテム。担当・期限が話されていれば含める。無ければ空配列
- related_notes: 候補のうち、今回と同じ案件・テーマ・定例の続きと言える過去ノート。候補の見出し（### の後）を
  そのまま返す。候補に無い名前は返さない。関係が薄いものは含めない。無ければ空配列
- carried_over: related_notes のアクションのうち、今回の会議で触れられたもの。「完了」「進行中」「未着手」など
  この会議で分かった状況を 1 項目 1 文で。今回話に出なかったものは含めない。無ければ空配列
- corrections: 音声認識が固有名詞・製品名・サービス名・専門用語を誤って書き起こしたと文脈から確信できる箇所の訂正表。
  from は文字起こし中の表記そのまま、to は正しい表記。
  - 同じ語の表記ゆれは文字起こし中で最も多い表記に揃える。カタカナで定着している語をローマ字にしない
  - 言い換え（例: リランク → リランキング）や、一般名詞としても読める語は含めない
  - 確信が持てないものは含めない。無ければ空配列
- title / summary / topics / actions の用語は、訂正後の文字起こしと同じ表記を使う
